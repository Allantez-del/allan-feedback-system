# Customer Feedback API Design

## Overview

The Customer Feedback System exposes a serverless HTTP API through Amazon API Gateway.

The API supports two operations:

- `POST /feedback` - public endpoint used by customers to submit feedback.
- `GET /feedback` - protected endpoint used by authenticated staff to retrieve feedback.

AWS Lambda contains the application logic and Amazon DynamoDB stores feedback records.

---

## DynamoDB Item Design

Each feedback submission is stored as one item in the `allan-feedback` DynamoDB table.

The partition key is:

`feedbackId`

Example item:

```json
{
  "feedbackId": "fb-8f3a21",
  "customerName": "Jane Doe",
  "email": "jane@example.com",
  "rating": 5,
  "category": "service",
  "message": "The customer support was very helpful.",
  "submittedAt": "2026-08-27T17:30:00Z"
}
```

## Field Definitions

- `feedbackId` - generated by AWS Lambda and used as the DynamoDB partition key
- `customerName` - optional customer name
- `email` - optional customer email address
- `rating` - required integer from 1 to 5
- `category` - required feedback category
- `message` - required non-empty feedback message
- `submittedAt` - timestamp generated by AWS Lambda

## Allowed Categories

The following categories are accepted:

- `service`
- `product`
- `delivery`
- `website`
- `complaint`
- `suggestion`
- `other`

# POST /feedback

## Purpose

The `POST /feedback` endpoint allows customers to submit feedback.

Authentication is not required because customers must be able to submit feedback without a staff account.

## Example Request

```
{
  "customerName": "Jane Doe",
  "email": "jane@example.com",
  "rating": 5,
  "category": "service",
  "message": "The customer support was very helpful."
}
```

## Successful Response

HTTP status:

`201 Created`

Example:

```
{
  "message": "Feedback submitted successfully.",
  "feedbackId": "generated-feedback-id"
}
```

## Validation

The Lambda function validates incoming feedback before writing it to DynamoDB.

The following rules are applied:

- `rating` must be an integer from 1 to 5
- `category` must be one of the supported categories
- `message` must be present and non-empty
- `message` must not exceed 2000 characters
- optional `customerName` and `email` values must be strings when supplied

Invalid requests return:

`400 Bad Request`

---

# GET /feedback

## Purpose

The `GET /feedback` endpoint allows authorized staff to retrieve submitted feedback.

Unlike the POST endpoint, this route is protected.

## Authentication

Amazon Cognito provides staff authentication.

API Gateway uses a JWT authorizer and expects a valid token in the HTTP Authorization header.

Example:

```
Authorization: Bearer <JWT_TOKEN>
```

A request without a valid token is rejected by API Gateway with:

`401 Unauthorized`

The JWT token must never be stored in source control.

## Successful Response

A valid authenticated request returns:

`200 OK`

The Lambda function reads feedback records from DynamoDB and returns up to 20 records ordered by `submittedAt` with the newest records first.

The current implementation uses a DynamoDB `Scan` operation.

This is suitable for the current demonstration workload but is not the preferred access pattern for a large production dataset. A production version should use a query-oriented data model, an appropriate secondary index, and pagination.

---

## Error Handling

The API uses HTTP status codes to communicate the result of a request.

| Status | Meaning |
| --- | --- |
| `200` | Feedback retrieved successfully |
| `201` | Feedback submitted successfully |
| `400` | Request validation failed |
| `401` | Authentication required or token invalid |
| `500` | Unexpected server-side error |

Unexpected internal errors return a generic client response rather than exposing technical implementation details.

Technical information required for troubleshooting is written to Amazon CloudWatch Logs.

---

## Security Design

The API follows separation between public submission and protected administration.

`POST /feedback` is intentionally public.

`GET /feedback` requires Cognito authentication through the API Gateway JWT authorizer.

The Lambda execution role has access only to the required DynamoDB table operations:

- `dynamodb:PutItem`
- `dynamodb:Scan`

Clients do not receive direct access to DynamoDB.

API communication uses HTTPS through Amazon API Gateway.

---

## CORS

The development API currently allows requests from all origins:

```
*
```

This simplifies testing because no permanent frontend domain has been deployed.

For a production application, `allow_origins` should be restricted to the trusted frontend domain.

---

## Current API Limitations

The current project intentionally remains small and serverless.

Important limitations include:

- GET currently uses DynamoDB Scan
- retrieval is limited to 20 records
- pagination is not yet implemented
- POST is public and therefore production abuse controls such as throttling or AWS WAF could be considered
- CORS currently allows all origins
- no custom API domain is configured

These limitations do not prevent the project from meeting its demonstration requirements, but they identify clear areas for future production improvement.
